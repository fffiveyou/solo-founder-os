# Paper Submission Helper Example

## Input

Project:
论文速投助手

Target users:
研究生、科研新人、第一次投稿用户。

Core problem:
用户不知道哪些期刊靠谱、容易投稿、审稿周期如何。

Current alternatives:
LetPub、导师推荐、小红书经验帖。

Why users may pay:
节省时间、降低踩坑风险、提高投稿效率。

Fastest MVP:
微信小程序 + 静态期刊数据库。

Distribution ideas:
小红书、研究生群、B站科研区。

---

## Expected Insights

The workflow should identify:

- strong real user pain
- beginner-focused positioning
- content-driven distribution
- high long-term data maintenance cost
- risk of becoming a database project
- better positioning as a “decision assistant”
  instead of a “journal database”

---

## Human Notes

This is considered a realistic solo founder project.

Main reasons:
- clear niche
- low MVP complexity
- strong searchable pain points
- suitable for content marketing
- suitable for AI-assisted development

Main risks:
- data maintenance
- low willingness to pay
- overbuilding database features
